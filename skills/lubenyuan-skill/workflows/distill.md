# lubenyuan-skill · distill 工作流（核销+沉淀）

> 路由来源: SKILL.md。建立: 2026-10-07(骨架克隆 qushitiange 版落地; 一批 09-17~09-23 手动增厚+批量, 二批 09-16/15/14/09/08, 见 persona 各修订记录)。触发: 每晚 check md 链; 或批量回填 **5 天/会话**(同 taoge backfill `--llm-batch` 制式, 降序逐日)。

## 定位

读当日 md `#### 卢本圆` 小节(五 bullet: 大盘定调/今日操作持仓/提及个股/画面增量/规则沉淀), 把可复用的东西沉淀进 `skills/lubenyuan-skill/persona/`。
**信息截止铁律**同 taoge distill: 只允许 ≤ 目标日期的素材(md 文件、rules.md/profile.md 现有内容), 禁止马后炮。

## 流程(两步, 顺序不可换)

0. **读素材包(10/17 A14②, 零 token)**: 会话开头一次 Bash `scripts/venv/Scripts/python.exe -X utf8 scripts/md/build_distill_pack.py --skill lubenyuan --date <日1>,<日2>,...`, 每天先 Read `downloads/distill_pack/<目标日>/lubenyuan.md`(当天小节/收评+同票行/近 5 天同票记录/同票规则全文+待验证索引/画像目录); 包里有的不再自己 grep/cat, 标"未展开/截断"的按行号补读; 非交易日顺延块不在包里, 照旧读挂载日 md; 脚本失败=照旧读原件。
   - 10/17 晚起: 每个目标日的收评等公共部分不再放进本人包, 在同目录 `downloads/distill_pack/<目标日>/_common.md`(需要大盘背景时读一次)
1. **核销**: rules.md 中 `[待验证]` 规则 vs 目标日期 md——L 系规则多为无时间词长期纪律, 永不核销只积累锚点/样本(锚链按日期升序, 回填发现更早实证=补"更早锚"); 有时间词者兑现改 `[md 验证 YYYY-MM-DD]`+样本+1+验证记录, 打脸改 `[已证伪 YYYY-MM-DD]` 不删+cases.md 立案; 未触发不动。原声直证可升格既有转述锚(如 L9 思想源头 9/15 直证)。
2. **提取**: bullets 分流——大盘定调/操作持仓→profile.md(行为统计: 交割单口径/节奏链/板块池/社区); 提及个股(带态度)→rules.md 对应 L 规则补锚, 新规则 L<下一号> 初始 `[待验证]`(单样本可入并标 [单样本](10/18 R27); 单样本框架也可放 profile 形势判断并标注样本1); 画面增量只沉淀看盘习惯; 规则沉淀 bullet→rules.md 主战场; 误判/踏空/检讨/神操作→cases.md 立案(格式同 taoge: 背景/判断操作/结果/自我归因/人格增量; 允许多日生命周期案, 后续走向可引 persona 已录事实)。**主料=持仓披露+交割单**: 仓位口径/成本/目标价变化优先入 profile 持仓透明度区与 L18(目标价+底仓规模)。**语言指纹**: 引用块新口头禅/比喻→language.md 口头禅行, 新 ASR 错字→其转写纠错词典(原声照录+注正字, 存疑标[?])。

## 纪律(同 taoge 六条)

1. 新增/修改必带证据锚点(日期+原话短句, ASR 错字首现注正字), 引不出原文不入库
2. 冲突不删, 标 `[已失效-市况变迁 YYYY-MM-DD]`
3. 改任一 persona 文件必须在其修订记录追加一行
4. 单样本也可进 rules.md(标 [单样本], 时间状态=待复核; 之后兑现升级、打脸降级; 10/18 用户定 R27: 我们是来赚钱的); 同时在 cases.md 记一条案例卡
5. 无可沉淀内容(空小节/未发稿日)是正常结果, 不硬凑
6. 结束时 stdout 哨兵: `DISTILL_OK {日期}`(批量会话逐日各打一行, 末行为当日)
7. 输出纪律(10/17 A14③): persona 只写变更/新增条目, 不整段重写、不复述 md 原文(锚点=日期+≤30 字原话); 用 Edit 局部改, 不用 Write 整文件重写; 最终回复每天只列改动清单 + 哨兵
8. 规则时间状态(10/17 晚用户批): 每条规则头下第一行是 `- **时间状态**: 建立 YYYY-MM-DD · 最后验证 YYYY-MM-DD · 状态 活跃|待复核|已否定(...)`(列表式规则写成下一行缩进子项 `  - 时间状态: ...`)。新增规则→写这一行(建立=目标日, 最后验证=最近证据日); 本次核销兑现或打脸了某条→把它的「最后验证」改成目标日; 导师的新做法否定了旧规则→旧规则**不删不改正文**, 只把状态改成 `已否定(YYYY-MM-DD, 由 Rxx 取代)`, 新做法另起一条; 活跃/待复核两态由 scripts/md/rule_time_state.py 每晚按最近证据日机械刷新, 不用手改。
