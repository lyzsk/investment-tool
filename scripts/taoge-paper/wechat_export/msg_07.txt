## 一、每日节奏（T 日）

| 时刻 | 动作 | 谁干 | 真实数据来自 |
|---|---|---|---|
| T-1 晚 ~21:00-23:00 | 探测桃哥新视频 → 下音频 → ASR（本地） → 纠错 → 注入 md → **我解读** → 产出 analysis JSON + **明日策略 watchlist**（候选票/触发条件/失效条件） → **沉淀**（新规则带 learned_before 追加进规则文件） | 重会话（~30-50k tokens) | B站（真实视频）、本地 ASR |
| T 09:36 | 盘前 checkpoint：读 watchlist + 隔夜外围（WebSearch) + 电报 md，下开盘决策 | 轻会话（~15k) | 腾讯实时行情、stocks md |
| T 10:36 / 13:36 / 14:46 | 盘中 checkpoint×3:watchlist 触发条件 vs 当日 m5 逐根比对，触发则决策 | 轻会话（~15k×3) | 腾讯 m5（含当日） |
| T 15:05 | 收盘结算：拉全天 m5+收盘价，逐笔对账、净值入库、记数据洞 | 轻会话+脚本（~20-30k) | 腾讯日线 |
| T 晚（循环） | 桃哥当晚视频出来 → 对比"他实盘 vs 我们 paper" → 进入下一轮 | 重会话 | 他视频里自曝的真实操作 |

**成交口径与回测完全一致**:checkpoint 时刻只看 ≤ 该时刻的 bar，成交 = 下一根 m5 bar 开盘价，买万2.5/卖万7.5。09:36 决策 → 09:35 bar 开盘价成交（已定型，无未来函数）。脚本断言 bar 存在，造不了假。

## 二、数据收集（DB 的"文件代孕")

建 `scripts/taoge-paper/`，每张未来要建的表对应一个 JSONL/CSV,**列名与 taoge.sql/k3inv.sql 完全一致**，假期手写代码时逐行 INSERT 即可，零迁移成本：

- `taoge_video.jsonl` / `taoge_transcript.jsonl` / `taoge_analysis.jsonl`（解读全文+明日策略）
- `taoge_mention.csv`（提及个股，次日收益回填 → verdict)
- `taoge_rule.jsonl`（沉淀的规则，**每条带 learned_before**,walk-forward 安全）
- `paper_run / paper_decision / paper_trade`(run_type='paper',decision 带 **info_cutoff**)
- `market_quote_daily.csv`（关注池日线，每天收盘追加）

另加两条防作伪/防扯皮设计：① 每个 checkpoint 的决策文件写完后算 sha256 追加进 `hashchain.log`,**先落哈希后拉新数据**，事后谁（包括我）都改不了历史决策；② `holes.log` 专记数据洞（视频没发/ASR失败/API挂）,**宁可记洞不编造**。

## 四、"万无一失"清单（我能想到的全部）

1. **状态单源**:`paper_state.json`（持仓/现金/净值/待触发watchlist）是唯一真相，会话崩溃、上下文压缩都丢不了——会话只是临时工，文件才是账本。
2. **防未来函数**：决策先落盘+哈希，再拉行情；settle 脚本断言成交 bar 存在；info_cutoff 逐决策留痕。
3. **PC 挂机保障**：任务计划程序勾选"唤醒计算机运行"+ 交流电源；会话方案见下面问题 1。
4. **断档自愈**：每次启动先查 `state.last_date`,missed 的环节按顺序补跑（昨晚视频没跑 → 先补跑再做今天的事）。
5. **桃哥停更/迟到**:23:00 无新视频 → 沿用前一日策略并在 holes.log 记洞，不硬编。
6. **B站 412 风控**：指数退避重试；连续失败 → 记洞 + 提示你手动看一眼。
7. **不用东财**:paper 是虚拟盘，全程不碰 em.ps1，不弹窗。
8. **9/30 晚自动出国庆复盘包**:paper vs 桃哥实盘 vs 上证，逐笔对照表 + 规则命中率 + miss 表，你假期第一天就能看。
9. **本周末（9/19-9/20）彩排**：市场不开门，但 9/18 的视频是真实的——周日晚上完整跑一遍"晚间重会话"，把 pipeline 所有坑提前踩掉；checkpoint 用 9/18 的历史 bar 干跑一遍。

## 修订：盘中 = 哨兵脚本 + 事件唤醒（不再按点开会话）

**哨兵（纯 node,0 token)**：交易日 09:20 由任务计划程序启动一个常驻进程，自己跑循环，15:10 自动退出：

| 时段 | 轮询间隔 | 检查内容 |
|---|---|---|
| 09:25-10:00（竞价→早盘） | **每 2 分钟** | 竞价结果（09:26 第一次拿到真实竞价量/价）→ 逐根 m5 |
| 10:00-11:30 / 13:00-14:30 | 每 5 分钟 | watchlist 触发条件 vs 实时行情 |
| 14:30-15:05 | 每 2 分钟 | 尾盘动作 + 收盘结算触发 |

哨兵只做**数值比较**，watchlist 里的触发条件由晚间重会话写成机械可判的 JSON（`跌破 192.76 且量比>1.5 → 止损`、`高开1-4% 且竞价金额板块前3 → 试错买`)。三种情况唤醒我（headless `claude -p`，自动带触发上下文）:

1. **触发命中** — watchlist 条件满足，叫我做最终裁决+落决策（含 info_cutoff + 哈希）
2. **盘中变量** — 持仓股 ±5% 异动、关注池批量跌停、板块急拉（板块接口免费），即"非计划事件"
3. **定时心跳** — 09:26（竞价+隔夜+k3盘前regime)、11:31、14:56（尾盘+k3决策） 这 3 个固定点必醒，其余全靠事件

这样 checkpoint 是**连续覆盖**的（早盘延迟≤2分钟），但 token 只花在有事的时候。预估每天真正叫醒我 3-7 次。

## 几个新增的关键设计

1. **k3 v0.2 竞价观察窗首次可执行** — 回测里标了"历史竞价不可得"的那条规则，09:26 的哨兵能拿到真实竞价数据，这 7 天正好做它的实时验证，直接进 paper 验证清单第一项。
2. **9/25 空窗处理** — 9/24 的 14:56 心跳自带"跨空窗+周末+外围3天"风险评估，按规则默认降仓/清仓并留痕；9/28 盘前心跳重启，state 冻结期间任何数据洞记 holes.log。
3. **决策哈希链不变** — 哨兵每次唤醒前后各落一次哈希，盘中高频也不破坏防作伪链。
4. **彩排升级** — 周日（9/20）晚跑真实晚间会话（9/18 视频）; 周一（9/21）就是你的第一个实战日，所以哨兵我用 9/18 的历史 bar 做回放压测，模拟"每2分钟喂一根 bar"验证触发逻辑，不等实盘才发现 bug。
5. **headless 权限** — 唤醒用 `claude -p` + 白名单（只允许读 scripts/、写 taoge-paper/、访问行情 API)，不开放全权限，这条周末配好给你过目。
