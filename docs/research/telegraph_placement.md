# 电报点名放在 chain 的哪里 · 可选位置 + 示例 + 对质量的影响（10/25，等你选）

> 背景：你 10/25 指出"06 写为什么不是追点名"逻辑反了——追点名负期望是已知事实，应该在选股时就摆出来；另外被点名涨停的票之后开板 / 炸板，正是想捕获的 T 字 / 回封。
> 数据见 `docs/research/telegraph_kind.md`（分类 v2，近 100 个交易日）。下面每个位置都可以单独开关，不是只能选一个。
> "影响"一栏：+ 是可能变好的地方，− 是可能变差 / 成本。

## 现状（已经在跑的）

- 必查清单里已有一行「电报点名」：`今天 HH:MM 电报摘要…; 历史: 点名后追进去次日平均亏(避雷), 点名时还没见顶的相对好 —— 见 telegraph-skill T1 / T2`（不分类别、不给分布）
- 06 写到被点名的票，代码在 why 末尾补 `HH:MM:SS CLS电报点名 链接`（给你回看用，不影响决策）
- 被点名的票**不会**自动进候选池 / 3 秒盘口；开板 / 炸板也**不会**叫醒任何线

## 可选位置

## 我的建议（不自信，等你选）

- 先上 **A + D + G + H**（零或几乎零 token，不改触发），**J** 看你要不要
- **E 先不做"叫醒"**，改成：A 里给出"点名后开板"那组统计 + 06 已有的 `board_dip` 条件单（执行器秒级判断开板、按价位区间买一次），让模型**提前**决定要不要接；等跑几天看 board_dip 真实成交再决定要不要加叫醒——这也符合"触发一次只改一条"
- **B** 可以先以"指引模式"上（记录有没有回应，不打回）
- **F 不做**

## 不自信点

- A 里用的类别统计格子很小（封板 / 冲板各 n=30），前后两半方向都不完全一致
- E 的"开板即接"统计用的是分钟收盘价，真实能不能在那一分钟成交没验证（尤其秒开秒封的）
- "关注它的线"的定义会直接决定 D / E 的规模
