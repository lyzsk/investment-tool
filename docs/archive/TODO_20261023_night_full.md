### 2.2 "太大了用索引" 会发生什么，是不是慢的原因

- 用索引 = 模型只看到每条一句话：①细节靠猜 → 拟人度上不去（今天土豆卖点规则只剩一句话、澳弘案例 0 条就是例子）②想看细节就得自己去读文件 → 每读一次多一个往返，**每个往返都把整段上下文重发一遍**；claude -p 今天中位 351 秒，多轮读文件是主要原因之一（置信 60%，没拆分计时）
- 所以 v3 的原则：**材料一次灌全**（芷影全部 skill 文本约 20 万字节 ≈ 7~10 万 token，Opus 5.5 上下文 100 万，装得下），靠缓存让后续轮次便宜；不靠索引省材料
- 缓存实测（今天）：claude -p 这 8 天命中率 79%~95%；直连 API 4%~8%，探针 18 次全 0（中转把直连请求分到不同上游）→ v3 不走直连 API

### 2.2a 索引的意义（你 18:4x 问）—— 索引是 "地图"，不是 "替代品"

- v2 的错用：只给索引一句话、把全文扣下 → 模型只能靠一句话猜细节（拟人度上不去的原因之一）
- 索引该干的四件事：①**目录**：放在全文前面，告诉模型 "有哪些、在哪一节"，长材料里帮它定位，减轻 "中间看不清" ②**第二层数据的导航**：库和历史文件灌不进去，索引告诉它有什么、在哪、怎么查 ③**脚本检索的钥匙**：规则编号 / 画像节标签让脚本按需精确取原文（必查项预先查好就靠它）④**引用锚点**：06 终裁写 "依据 R8 / R21"，脚本能核对它是不是真有这条、是不是看过全文
- v3 用法：第一层 = **索引 + 全文** 一起给（索引在前当目录）；第二层 = 索引 + 查询工具

### 2.2b 你 18:2x 定的原则："本地数据全给模型 + 加索引，不设 20KB / 64KB 这种上限" —— 方向对，按体积分两层落地
