## 二、harness 是什么

### 核心思想

把模型当成一个**能力很强、但不可信的函数**：
`模型(材料) → 文字`。harness 就是包在它外面的一圈代码：

```
  材料（代码备齐、截到触发时刻）
      ↓  ① 输入闸：喂什么、不喂什么、缺料怎么办
  模型（只能用被放行的工具）
      ↓  ② 工具闸
  输出（必须是规定格式的 JSON）
      ↓  ③ 结构闸  ④ 内容闸  ⑤ 数值 / 硬规则闸
  推送 / 记账
      ↓  ⑥ 行为闸（多频繁）  ⑦ 推送闸
  每晚核销
      ↓  ⑧ 事后核验闸（影子账 + 校准）
```

**三条原则**：
1. **确定的事交给代码，判断交给模型**。概率、价位、涨跌停、T+1、股数——代码算；"这组样本今天适不适用、主线换没换"——模型判断。
2. **每道闸都要留痕**。拦了什么、为什么拦，写进日志。10/23 推送被置信度闸悄悄拦掉 4 条，就是没留痕的教训。
3. **按后果选"默认放行"还是"默认拦截"**（见第三部分 3.8 表）。

### 八道闸逐个说

**① 输入闸（喂什么）**
- 材料分三层：常驻（每次都给，进缓存）/ 按候选机械检索（只给命中的规则、案例、统计）/ 索引（模型想查再查）
- 所有材料按触发时刻截断（防未来函数）
- 关键材料缺了（相似日查询失败、盘口断流）→ **大声失败**：在材料里写明"缺 xx，本项不许给概率"，不是写一行"查询失败"了事
- 案例必须带正 / 负标签

**② 工具闸（能动什么）**
- 只读：Read / Grep / `./q`；禁止写文件、禁止联网、禁止任意 Bash
- 限次数：一次触发最多查 N 次，查满了就必须直接作答（防止无限查、烧 token）

**③ 结构闸（格式）**
- 输出必须是一段 JSON，字段、类型、枚举值都写死（模板见 3.4）
- 不合格 → 把错误原文回给模型重写一次 → 还不合格 → 用上一版计划，记日志、推一条告警

**④ 内容闸（禁用词 / 必含项 / 引用核验）**——最能体现"约束"的一道
- 禁用词：没有数字支撑的定性词（"大概率""稳了""必然""肯定"）、否决词（"别买""不做"——你 10/21 定的只给数据不否决）
- 必含项：每个概率带来源编号；每个情景写失效条件；每张单写"目的 / 收尾 / 最怕什么"
- 引用核验：模型写的概率必须和来源编号对应的数值一致（允许 ±1 个点）；引用的导师案例必须查结果，负样本不能出现在"依据"里
- 自洽：同一只票各情景概率加起来 ≈ 100%

**⑤ 数值 / 硬规则闸**：直接复用 `rule_gate.py` G1~G7

**⑥ 行为闸**：每天触发上限、冷却 / 去抖、时间窗（如 14:57 后不出新单）、每天花费上限

**⑦ 推送闸**：`wx_send.py` 置信度闸 + 来源白名单 + 被拦落账（10/23 已修）

**⑧ 事后核验闸**：计划影子账、概率校准（说 70% 的那些实际兑现几成）、你的决策日志 → 每周回看

## 三、你要手动配的东西

> 下面每一节是一个"配置块"。建议你把它们整理成一个文件 `scripts/live/harness.yaml`（还不存在，你建）；我接线时按这个文件读。不确定的项可以先空着，我会用括号里的默认值。

### 3.1 时间表（什么时候跑哪一步）

```yaml
schedule:
  plan_at: "08:40"          # 盘前计划开跑时刻(默认 08:40; 要读到发哥 07:0x 的蒸馏和财联社早报)
  plan_deadline: "09:10"    # 计划最晚落地, 超时推告警并用昨晚的预案
  auction_check: "09:20:30" # 竞价对照计划(零 token 先判分支, 偏离才叫模型)
  tail_check: "14:45"       # 尾盘检查
  no_new_after: "14:57"     # 之后不出新单
```

### 3.2 材料清单（输入闸）

```yaml
inputs:
  resident:                 # 常驻, 进缓存; 合计目标 ≤ 4 万 token
    - account               # 你的持仓 / 成本 / 可用(从 live_account / 你报的数)
    - market_panel          # 盘面情绪面板: 涨停 / 炸板 / 跌停 / 封板率 / 梯队 / 13 档分布(待建)
    - theme_strength        # 盘中题材强度(待建)
    - mentor_digest         # 全部导师 + 发哥 + 三 UP 的机械汇总表, 每人一行(待建)
    - yesterday_md_digest   # 昨天 md 的结构化摘要, 不放全文
  retrieved_per_candidate:  # 每只候选按需检索, 每只 ≤ 3000 token
    - rules_hit             # 被这只票命中的导师规则原文
    - cases_hit             # 同形态案例, 必须带 正 / 负 / 平 标签
    - stats                 # 代码算好的概率(见 3.3), 每条带 Q 编号
    - peers                 # 同炒作逻辑邻居(同游资 / 同题材 / 同梯队; 待建)
  index_only:               # 只给目录, 模型自己查
    - ./q 资料目录
  on_missing: fail_loud     # 缺料: fail_loud = 写明缺什么、该项禁止给概率(推荐) / skip = 静默跳过
  max_candidates: 8         # 一次最多看几只票(默认 8)
  skills_mode: digest       # digest = 全部导师走机械汇总、只读命中的 3~5 位原文(推荐) / all = 全文都喂(贵且易稀释)
```

### 3.3 概率来源（谁能产生数字）

```yaml
probability:
  source: code_only         # 只有代码能产生概率; 模型只能引用 Q 编号
  min_n: 15                 # 样本少于这个数: 概率按 odds.prob() 向参照组收缩, 并标"低置信"
  report: [n, mean, median, p10, p90, worst, best]   # 每个分布必须报全(你 10/23 定)
  queries:                  # Q 编号对应的查询(已有的直接用, 待建的标出)
    Q-same:   本票同形态日          # order_ctx ④ / hypo_test.py
    Q-sim:    相似日(转债)          # ./q similar
    Q-window: 日线走势相似          # ./q window
    Q-strong: 强势股次日            # strong_next
    Q-board:  开板 / 回封           # board_knowledge
    Q-touch:  挂单触及概率          # fill_prob
    Q-peer:   同逻辑邻居次日        # 待建 ./q peers
    Q-tg:     电报点名次日          # telegraph-skill T1~T4
  model_adjust: allowed_with_reason   # 模型可以说"下调 / 不适用", 但必须写理由, 且不能给新数字
```

### 3.4 输出格式（结构闸）

盘前计划，每只票一条：

```json
{
  "market": {
    "mainline": "机器人",                 // 主线
    "state": "退潮|冰点|修复|主升|分歧",
    "big_cap": "偏弱", "small_cap": "偏强",
    "evidence": ["E3", "Q-tg-T1"]
  },
  "skills_view": [                       // 各 skill 怎么看(机械汇总里来, 模型只做取舍说明)
    {"skill": "芷影攫心", "stance": "看多|看空|观望", "rules": ["R9"], "pos_cases": 2, "neg_cases": 1}
  ],
  "picks": [
    {
      "code": "002307", "name": "北新路桥",
      "scenarios": [                     // 竞价 / 开盘情景, 代码先划档, 模型填动作
        {
          "when": "竞价 ≥ +5% 且未匹配买 > 卖",          // 必须可机械判定
          "prob": {"q": "Q-same#3", "value": 0.42},      // 只能引用 Q 编号
          "action": "等回落买|开盘买|不动|卖",            // 枚举
          "buy_signal": "S2",                            // 只能从信号库(3.5)选编号
          "buy_zone": [3.60, 3.66],
          "exit_plan": {"if_close": "收在 3.70 上方", "next_day": "第二波冲高卖", "q": "Q-same#5"},
          "p_next_sell_above_buy": {"q": "Q-same#5", "value": 0.61},
          "invalid_if": "开盘 5 分钟跌破 3.55",
          "fear": "游资出货、开板不回封"
        }
      ],
      "not_reliable": ""                 // 样本不适用时写原因, 此时 scenarios 里不许有 value
    }
  ],
  "not_doing": [{"theme": "算力", "why": "不在能力圈 / 已见顶"}]   // 看到了但不做(你 10/23 要求)
}
```

### 3.5 分时信号库（买卖点只能从这里选）

```yaml
signals:                    # 每个信号必须能被代码在 3 秒盘口上检测到; 触发 → 零 token 推微信
  S1: {name: 急跌后拉起, rule: "5 分钟内跌 ≥ 2σ 后, 1 分钟内收回一半跌幅且站上均价线"}
  S2: {name: 回踩均价线不破, rule: "价格回到均价线 ±0.3% 内, 3 分钟不破并回升"}
  S3: {name: 二次冲高, rule: "开盘冲高回落后, 再次接近前高(差 ≤1%)且量能 ≥ 第一波 70%"}
  S4: {name: 炸板回封, rule: "开板后 N 分钟内重新封住涨停"}
  S5: {name: 尾盘拉升, rule: "14:25~14:45 低点后 10 分钟内涨 ≥ 1.5%"}
  # 你自己加: 名字 + 能写成规则的条件; 写不成规则的不能进(模型会用来搪塞)
```

### 3.6 内容闸（禁用词 / 必含项）

```yaml
content_gate:
  banned_words:             # 出现就打回
    - 大概率                 # 必须写成百分比 + Q 编号
    - 稳了
    - 必然
    - 肯定
    - 别买                   # 只给数据不否决(10/21)
    - 不做
  banned_unless:            # 有条件才允许
    观察: "必须同时写叫醒条件"
    等待: "必须同时写等到什么价 / 什么信号"
  required:
    - every_prob_has_q      # 每个概率有 Q 编号, 且数值和 Q 一致(±1 点)
    - every_scenario_has_invalid
    - negative_case_not_in_evidence   # 负样本只能在 fear / 风险里
    - scenario_probs_sum_100          # 同一只票各情景概率和 95%~105%
  on_fail: retry_once_then_previous   # 重写一次, 还不行用上一版 + 告警
```

### 3.7 行为闸

```yaml
behavior:
  max_model_calls_per_day: 40
  cooldown_sec: 180          # 同一只票两次叫模型最少间隔
  manual_trigger: true       # 你手动加触发(微信"重算 北新")
  daily_budget_cny: 80       # 当天花费到这里停自动触发, 只响应你的手动触发
  wake_without_model: [S1, S2, S3, S4, S5, 到价, 破位]   # 这些只推提醒, 不叫模型
```

### 3.8 失败策略（默认放行还是拦截）

| 情况 | 推荐 | 理由 |
|---|---|---|
| 关键数据缺 / 查询失败 | **拦截**（该项不给概率，写明缺什么） | 带着缺数据下判断最危险（10/23 相似日查询失败没人发现） |
| 输出格式不合格 | 重写一次 → 用上一版 | 不能没有计划 |
| 内容闸不过（禁用词 / 引用不一致） | 重写一次 → 删掉不合格的那条，其余照发 | 一条坏不连累整张表 |
| 硬规则闸不过（T+1 / 涨跌停 / 资金） | **拦截**该单，告诉你为什么 | 交易所会拒单 |
| 推送 | **放行 + 留痕** | 你收不到最糟 |
| 模型超时 / 限流 429 | 等下一分钟重发；超时用计划里的预案 | 盘中不能空窗 |

### 3.9 Claude Code 本身的 harness（交互会话用，你自己在 settings 里配）

> 我不碰 `~/.claude/settings*.json`（10/9 立法），下面是你自己配时的参考。

- **权限**：`permissions.allow` / `permissions.deny`——盘中会话只放行只读命令和 `wx_send.py`，禁止写业务库、禁止 git
- **hooks**：
  - `PreToolUse`：工具调用前检查（例如拦截对 `investment_tool` 库的写 SQL、拦截改 `chain_flags.txt`）
  - `PostToolUse`：工具调用后检查（例如 Write 了 `docs/TODO.md` 后自动 scp 到 PC3）
  - `Stop`：每轮回答结束时检查（例如回答里有"大概率"却没有百分比 → 提醒补）
- **CLAUDE.md / 记忆**：放规矩（你现在的思维八法、三条纪律），是"软约束"；硬约束要靠 hooks 和代码闸
- **claude -p 后台**：`--allowedTools` / `--disallowedTools`（v3 现在就是只放 Read / Grep / Glob / `./q`）

### 3.10 事后核验（影子账 + 校准）

```yaml
review:
  shadow_book: true          # 零 token 按计划机械执行记账(不需要模型)
  decision_log: true         # 你每笔: 照计划 / 偏离计划 + 一句理由(微信回一个字也行: "照" / "偏 理由")
  calibration_buckets: [0.3, 0.5, 0.7, 0.9]   # 每晚统计: 说 50~70% 的那些实际兑现几成
  weekly_report: "周六 10:17"
```

## 四、配置顺序建议

1. 先配 **3.4 输出格式** 和 **3.5 信号库**——这两个决定模型能输出什么、程序能盯什么，其余都围着它们转
2. 再配 **3.6 内容闸** 和 **3.3 概率来源**——决定哪些话不许说、数字从哪来
3. **3.1 / 3.2 / 3.7** 先用默认值，跑一周再调
4. **3.9** 是你自己的 Claude Code 设置，和实盘线无关，可以随时配
5. 配完告诉我，我按配置接线：先接"代码算概率 + 计划表 + 校验闸 + 影子账"，再接竞价对照和盘中触发
